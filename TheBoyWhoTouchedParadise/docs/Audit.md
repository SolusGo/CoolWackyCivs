# v25 stability audit — 2026-10-12

Scope: BNW + installed Community Patch v151, whose manifest identifies **5.4.6**. All mechanics, numeric bonuses, costs, durations, narrative and artwork are preserved. No Eternal Number Ten or other civilization gameplay file is changed.

## Confirmed defects and changes

| Confirmed problem | Exact change |
| --- | --- |
| A popup **request** is not proof of an open popup. CP TechPopup ignores requests for other players; TechTree can toggle closed and emit Processed synchronously from an earlier request listener. The old Journey listener could then set a blocker after completion. | `UI/ParadiseJourney.lua` yields its own modal on requests without saving a request blocker. Only Shown records a popup. A bounded list of actual BNW/CP contexts is inspected on meaningful lifecycle events. Known hidden contexts clear stale records; map selection, selection-mode return, city/diplomacy exit, BulkShowUI and owner-turn start reconcile unregistered popup records when no known fullscreen screen remains visible. |
| Boolean popup flags could stay latched when a screen omitted its expected Processed callback. Treating every close identically also fails Culture Overview's ordering. | Preserve independent blockers for nested screens. Known completion marks only that screen as closing: Culture Overview calls Processed **before** DequeuePopup; Policy calls it from its hide handler; CP TechTree dequeues before Processed. Reopen requests/Shown clear that closing mark. An ignored request recovers on the next map-return event. |
| Modal ownership was represented only by a local boolean; engine/parent hide and context shutdown had no explicit cleanup. | Use native `UIManager:IsModal(ContextPtr)` before pushing or popping this context. Parent hide and shutdown release it idempotently. Popup/city/diplomacy entry yields it. Pending stories remain in gameplay state, resume after obstruction and still require **Continue the Journey**; Escape does not acknowledge the finale. |
| Paradise subscribed to PlayerCanGiftUnit but depended on The Filthy Realm to enable its event group. | Add only `EVENTS_MINORS_INTERACTION` to Paradise core SQL and its generator's existing `UPDATE ... SET Value=1` convention. `CvUnit::canGift` and `canDistanceGift` wrap the three-argument test-all hook in that exact option. The unit-type handler is unchanged. |
| A duplicate UnitCreated arriving before the native counter increment could call `settleBirths`, discard unchanged pending evidence, then fail the already-recorded Created claim. | In `Lua/ParadiseRuntime.lua:onCreated`, resolve the unit and check its existing stable Created claim **before** settling births. The existing key, claims, evidence and payout path remain unchanged. A failing pre-fix regression reproduced the lost legitimate 2-Dream reward. |

No recurring timer, update handler, per-frame check or full-map scan is added. The compact tech chooser's authoritative path is `/InGame/WorldView/InfoCorner/TechPanel/TechPopup`; engine-loaded diplomacy also checks `/LeaderHeadRoot`. Screen handlers belonging to the game or other mods are never replaced. Unknown third-party popup contexts require their normal Processed callback or a subsequent meaningful map-return event; returning while a known native fullscreen context is still visible never clears its blocker.

## Native GP audit: preserved attribution

The matching [Release-5.4.6 DLL source](https://github.com/LoneGazebo/Community-Patch-DLL/tree/Release-5.4.6/CvGameCoreDLL_Expansion2) and installed BNW/CP UI were inspected before editing. Older cached `.tools/cp-v151-audit` files differ from this release; this audit used the matching `.references/psj-cp-5.4.6` files and freshly retrieved tagged `CvCityCitizens.cpp` / `CvReligionClasses.cpp`.

- **Scientists, Engineers, Merchants, Writers, Artists, Musicians:** [CvCityCitizens::GetSpecialistUpgradeThreshold](https://github.com/LoneGazebo/Community-Patch-DLL/blob/Release-5.4.6/CvGameCoreDLL_Expansion2/CvCityCitizens.cpp) uses the city's **owner's** created counts, plus owner/trait/speed/start-era/handicap factors. It does not use city-local generation progress or a city's GP-rate bonus. Using the current capital is therefore harmless for births in another city and capital transfers. SEM share the default CP pool; GWAM use distinct counts. DoSpawnGreatPerson initializes the unit before incrementGreatPersonCount. The installed `GLOBAL_TRULY_FREE_GP=1` excludes free counts from these thresholds.
- **Generals:** [CvPlayer::createGreatGeneral](https://github.com/LoneGazebo/Community-Patch-DLL/blob/Release-5.4.6/CvGameCoreDLL_Expansion2/CvPlayer.cpp) initializes before incrementing its created counter. The exposed getter with `true` excludes free Generals. No new counter is needed.
- **Admirals:** the same source sets naval experience before creating the Admiral, increments the own and team threshold modifiers after init, then consumes naval experience. The existing earned-meter snapshot plus full threshold increment is retained. Threshold increments grow after every tenth counted Admiral; the existing minimum-step comparison still accepts the larger native increase. Free Admirals raise the modifier too, which is why the earned-meter requirement matters.
- **Prophets:** [CvPlayerReligions::GetCostNextProphet](https://github.com/LoneGazebo/Community-Patch-DLL/blob/Release-5.4.6/CvGameCoreDLL_Expansion2/CvReligionClasses.cpp) uses the player's created Prophet count and excludes free Prophets when requested. [CvLuaPlayer::GetMinimumFaithNextGreatProphet](https://github.com/LoneGazebo/Community-Patch-DLL/blob/Release-5.4.6/CvGameCoreDLL_Expansion2/Lua/CvLuaPlayer.cpp) requests that exclusion via the installed free-GP option. Native earned spawns pass non-free counting after init. Faith purchases emit CityTrained, so they remain excluded even when a native cost rises.
- **Produced/purchased units and conversions:** installed [CvCity.cpp](https://github.com/LoneGazebo/Community-Patch-DLL/blob/Release-5.4.6/CvGameCoreDLL_Expansion2/CvCity.cpp) and [CvUnit.cpp](https://github.com/LoneGazebo/Community-Patch-DLL/blob/Release-5.4.6/CvGameCoreDLL_Expansion2/CvUnit.cpp) confirm the existing CityTrained and UnitConverted exclusions. Direct InitUnit does not increment GP creation evidence. Sequential nearby births settle previous evidence before taking the next snapshot.

CP exposes no authoritative earned-birth event or Admiral/Prophet count getter for these paths. Perfect attribution across arbitrary other mods remains unavailable: a script can intentionally use a native **non-free** creation helper; a free Admiral injected during an earned-meter crossing can mimic the available evidence; Prophet faith cost includes belief/trait modifiers, which can change between creation and settlement. Those conditions cannot be reliably distinguished with the exposed APIs. No speculative counters or invented hooks were added. Ordinary native/free/purchased/scripted-InitUnit/conversion paths are covered; native Admiral/Prophet timing still needs live verification.
