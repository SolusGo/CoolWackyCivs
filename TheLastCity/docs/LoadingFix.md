# Council loading and Settler correction — 2026-10-11

The installed collection's manifest named the Council add-in file `Last City survival and management interface`, placing the XML path in its display name. The actual native `Lua.log` recorded Community Patch's `InGame.lua:1340` failing to resolve that filename (`addinFile` was nil). No Last City startup occurred, so the Council and its gameplay handlers, including the Settler veto, never loaded.

The project had its entry-point fields in `Type`, `FileName`, `Name`, `Description` order. Firaxis ModBuddy interprets these fields positionally and requires `Type`, `Name`, `Description`, `FileName`. The project and integration helper now use that order. The Python builder rejects incorrect order or unregistered entry-point files instead of generating a valid-looking package from a project ModBuddy would miscompile.

The native `NoAnnexing` trait now blocks Settler training and purchase even if Lua fails to load. Community Patch Release-5.4.6 `CvPlayer::canTrainUnit` implements this restriction. Initial free founding units bypass training eligibility, so Last City retains its normal starting Settler and unit-class mapping. Manual annexation is also disabled, consistent with the one-city rule. The Lua training veto no longer depends on a saved capital being initialized. A single `[LastCity] Survival runtime loaded` log message records successful startup.

Validation now enters the Council through a fresh Lua context, confirms that it loads gameplay and registers each handler once, and exercises the launcher and all tabs. A separate regression checks training before capital initialization, the starting city's founding and subsequent founding restrictions. The focused suite passes 45 groups. All sixteen civilization suites and both package archive integrity checks are required for this correction.

On this machine, the real Firaxis `GenerateModInfo` task produced all eighteen correct entry points, matching the Python manifest and resolving to existing files. This check generates a manifest under `.tools/modbuddy-entrypoints`; it does not deploy files or invoke ModBuddy's clean/deploy targets. Corrected UI rendering and native Settler eligibility still require a game smoke test after reinstalling the rebuilt package and restarting the modded game. Installed mod files and game caches were left untouched.
